# 优化实施记录与上线说明

日期：2026-10-27。基于 `c94871e`；本文记录本次实际代码改动，与改造前的 architecture-review 文档区分。尚未部署、推送或修改远程 D1。

## 已实现

| 范围 | 改动与效果 |
| --- | --- |
| 七类发布接口 | 统一 begin/chunk/status/commit；每批最多 10 行、请求体最多 64 KiB；Worker 不再反复解析整个市场；筛选单批最多 41 条 SQL。 |
| 中断恢复 | 同一产物、同一 runId，服务端返回已接受批号；重复批次幂等，改动内容、重复标的和缺失批次拒绝提交。数据和批次确认同事务写入。 |
| 版本一致性 | 筛选和辅助数据先写不可变版本，完成后原子切换生效指针；旧任务按源日期及生成时间不能回滚新版。补充股票不替换全市场。 |
| 行情 | 独立 live_quotes，按标的报价日期和时间单调更新；允许逐标的生效，不声称整个市场行情同时切换。 |
| 查询 | 筛选和规则分页固定因子 snapshotId；缺失版本返回 409；行情仍可刷新，价格排序不构成行情快照。规则检查所有依赖，按需 JOIN，能力校验覆盖率和有效日期。 |
| 采集与计算 | 日线覆盖不足 98% 拒绝发布；定时收盘任务检查预期交易日；实时行情采集覆盖不足 98% 失败；辅助数据提交至少覆盖当前股票池 80%。 |
| 历史数据 | Parquet 日期过滤下推、临时文件原子替换；前复权重叠区间变化时重建历史，重建不完整则失败，避免拼接不同复权基准。技术因子按股票计算后仅保留末行进行横截面评分。 |
| 财务 | 缺失值和非有限值转换为合法空值；按每股最新已披露报告取数，回溯最多五个报告期，保留每行报告期及公告日；覆盖率不把 ETF、指数计入股票池。 |
| 指标与推荐 | 修复窗口最大回撤；百分比单位统一展示/导出；推荐冻结首次发布基准和 technical-v3 版本，没有基准就不展示跟踪收益；去除虚构推荐理由。 |
| 前端 | 修复详情参数、北交所链接；请求序号防止迟到结果覆盖；按页面加载部分功能；刷新任务自动轮询并在终态重载；仅 401 清除登录态；规则分页、自选/策略分批读取；CSV 转义及公式注入防护；拆出详情和推荐组件。 |
| 鉴权与任务 | 登录限流在密码派生前执行；账户移除/密码变化使旧会话失效；数据库限制一个活跃刷新任务，过期任务释放，终态不接受迟到回调回退。 |
| 缓存与观测 | 公共聚合接口 15 秒缓存，不缓存用户态；缓存写入故障不影响成功响应；发布日志包含 requestId、runId、批号、字节数、SQL 数、耗时；增加数据就绪检查。 |
| 工作流 | Python 使用 uv.lock；不可变历史和筛选发布包先保存到 R2；增加原产物恢复工作流；采集重试与发布分离；辅助失败在汇总显示实际 outcome；交易日门禁、超时和 CI 校验。 |
| 清理 | 日常调用有界清理：90 天外、非活跃、非最近两个版本的数据，每请求最多删 100 行；绝不删除承载自选外键的股票身份。行业资金流 persistHistory 仍在提交时保存最多 300 行日快照。 |

## 字段约定

| 字段 | 单位 / 时间含义 |
| --- | --- |
| ret5d / ret20d / ret60d、volatility20、maxDrawdown60 | 比值，0.1 表示 10%；波动率按现有技术因子的年化定义。 |
| pctChange、turnoverRate、财务同比及 roe | 百分数，10 表示 10%。 |
| 资金流、总市值、营业收入和净利润 | 人民币元，沿用来源标准化口径。 |
| tradeDate | 历史日线因子日期。停牌等旧日期允许保留，过期行不参与当日评分。 |
| quoteDate / quoteTime | 源报价时间；与因子日期分开显示。 |
| reportDate / announcementDate | 每股报告期 / 公告日，不用全局最新报告期覆盖所有股票。 |
| generatedAt / source_time | 发布产物生成时间，用于同日任务排序；服务接收时间另存 started_at。 |
| tracking.returnPct | 相对冻结基准的价格收益百分数，不是过去 20 日收益，也不是含分红、拆股处理的总收益。 |

## 上线步骤

1. 保留当前 D1 备份与历史 R2 对象；确认生产 PUBLISH_URL、PUBLISH_SECRET、SESSION_SECRET、固定账户及 GitHub/R2 secrets 配置完整。
2. 从同一代码版本完成 `pnpm install --frozen-lockfile`、`uv sync --locked`、下方检查。Node 使用 22，Python 使用 3.12。
3. 应用 `worker/migrations/0023_versioned_datasets.sql`，再部署本版本 Worker、静态前端与发布客户端。部署工作流已在部署前执行远程增量迁移。迁移保留原表，新视图在没有新生效版本时回读原数据。
4. 新 Worker 仅接受 v2，旧发布器收到 426，必须同批升级；避免旧工作流跨越升级窗口。现有登录会话需要重新登录一次。
5. 执行收盘流水线；观察各数据集 completedAt、数据日期、行数与质量；检查 `/api/ready`（首个 v2 全市场版本前返回 503）及页面数据。
6. 发布中断时运行 **Resume preserved screener publication**，输入原 daily workflow run ID。它从 `publishes/{runId}/screener.json` 取原包，续传已确认批次，不重新抓取或生成基准。未完成任务一天后过期，过期后需重新构建发布包。
7. 首次线上运行采集 Cloudflare CPU、内存、D1 rows_read/rows_written、每请求耗时与失败率，确认有余量后再调整每批 10 行。不要把本地 SQLite 时间当作 Worker CPU 预算证明。

回退边界：迁移是新增表/视图，旧表仍保留；旧 Worker 只看旧表，回退会显示升级前数据。回退必须同步恢复旧发布客户端；不能认为指针会自动把新版本数据复制回旧表。

- Worker：`pnpm test:web`，22 项通过；使用真实 SQLite 执行全部迁移和事务，包含 6000 行/600 批、续传、冲突、五种辅助数据、行情顺序、因子分页、清理、鉴权和刷新状态检查。
- `pnpm lint:web`、`pnpm build` 通过。Wrangler deploy --dry-run 成功识别 AUTH_LIMITER；未执行真实部署。
- 浏览器模拟 API 冒烟检查通过：详情深链、推荐无基准收益为空、刷新结束按钮恢复、第三方图表备用链接。此项不是连接生产数据的端到端验收。
- 仍需线上验证平台 CPU/内存与查询成本；本次没有可用的生产执行轨迹，不能承诺再无 1102。
- 第三方数据源仍可能故障；部分 AkShare 内部网络调用没有统一可配置的逐请求超时，工作流整体超时作为最终边界。第三方图表存在网络/CORS 限制，提供外部打开链接。
- 发布 manifest 的整包摘要用于绑定任务，服务端逐批计算摘要验证重传内容；服务端不重新拼接整包计算摘要。发布接口仍依赖共享密钥的可信客户端。
- 补充股票快照为保持可搜索暂不自动删除已完成版本；后续需按标的压缩补充层。原始 legacy 表、行业日历史及 R2 不可变对象未自动删，R2 生命周期规则需单独配置。当前不是全存储无限期增长治理的终点。
- 当前会话固定的是日线因子版本；实时行情和辅助数据可更新，若需要严格跨数据集回测或全量导出，需要额外冻结这些版本。
- 长期含分红总收益、来源字段级修订合并、全量统一 schema 代码生成、预计算所有聚合页没有在这次改造中引入。先用实际 rows_read、CPU 和业务需求决定进一步工作。
